Performance, with receipts

Every number on this page is a dated, reproducible receipt — the harness, corpora, and corrupted cases are committed, every runner asserts full consumption before a timing counts, and losses publish with the same prominence as wins. That last rule is the clause that makes the rest of the page worth reading.

The honesty clause, current edition: the VM now sits 1.35× behind tree-sitter's raw C automaton on JSON throughput — down from 37× behind at the 1.5.1 baseline — and tree-sitter's incremental editing stays faster in absolute terms. Those rows sit at the top of this page on purpose, next to the three rounds that closed the gap. A benchmark suite you can't lose in public can't be believed when it wins.

The climb since the 1.5.1 baseline (1.073 µs/byte — 37× behind): the Scan campaign (bulk class-run kernels + scan-dispatch inlining) took 1.073 → 0.079; the dispatch-depth relaxation (the charset merge absorbing the per-char shape) 0.079 → 0.0599; and Phase 0 pooled writes (the packrat memo's multiply-xor hasher + pre-size, cached shape-tag/name interns, value-stack tail-store) 0.0599 → 0.0418. Every step interleaved-A/B'd with byte-identical trees — the speed never bought a different parse. The remaining 1.35× is profiled (the VM dispatch loop, the per-char scan kernels, then per-rule LR routing behind the determinism prover), and the differentiator stands: the typed AST output tree-sitter's flat CST never produces. The VM is ahead of Lark LALR (8.8×) and ANTLR python (47×) on the same corpus.

Error recovery — corrupted JSON

The recovery spine replays the unchanged prefix forward from byte 0 with the same probe the resync rounds use: recovered iterations exist as real spans and keep the original nesting — structure recall jumped 52.8% → 67.5% and null recoveries fell 24 → 0 in the round that halved the windowed-TED gap. The residual 0.059 vs 0.023 is the corruption site itself: tree-sitter hole-punches an ERROR node where the clean tree had a subtree; parsanol skips the junk span — closing it further means emitting error-node-shaped placeholders for skipped spans (a shape decision, not a recovery one). The diagnostic wins are held outright: the deepest-failure position tracks the corruption cause; tree-sitter's ERROR regions start far from it.

Constrained decoding — the mask oracle

Grammar-valid token masks compiled from the checksummed artifact (artifact + a tokenizer's decoded vocabulary → per-step valid-token sets), receipt dated 2026-11-19:

100% mask validity

200/200 grammar-valid generations on both harness grammars (ISBN + JSON), validity judged by the artifact oracle itself.

5.8% overhead

The end-to-end constrained loop costs 5.8% of a 10 ms/token model forward pass on ISBN — the grammar costs noise against the model.

Free backtracking

The relaxed rollout: when the model paints itself into a corner (a dead brace with no live continuation), the loop pops the dead pick, bans it, and re-masks — every re-mask is a fresh oracle parse. FSM mask compilers cannot offer this.

The state oracle is the recovering envelope's consumed position: a token extends the prefix iff the parse consumes past the boundary — a dead end never masks the model into an impossible state. 1.5.8 ships the llguidance-compatible TokenBitmask emitter (little-endian per-step sets a logits processor consumes).

The artifact economics

Performance is also the load path and the per-parse fixed cost — the numbers that decide whether shipping a grammar as data is practical:

The byte-checksum fast tier

One O(bytes) hash pass over the exact file bytes: ~5 ms on a 1.24 MB artifact, versus the 400–640 ms canonicalization the canonical checksum alone would cost on every load. Byte-level tamper detection before any parse work; older loaders fall back to the canonical tier unchanged.

The per-parse caches

Decoded entries and grammar analyses computed once for the parse-many pattern (PreparedGrammar): 7.5× on tiny-input parses — the setup/eval overhead that dominates small inputs, amortized.

The regression gate

Benchmark receipts ride CI with a regression gate: a train that loses numbers without a named cause doesn't merge. The receipts are evidence and a fence at the same time.

Measured, then honestly discarded

The arena-locality optimization was implemented, measured with Cachegrind counters, and falsified — recorded as a negative result. Perf claims here are survivorship-free.

Methodology

  • Shared corpus — every engine parses byte-identical documents; document hashes are committed per receipt.
  • Native runners — each engine runs its canonical binding; no cross-language handicaps for anyone.
  • Full-consumption proof before timing — a parse that stops early or errors is not a benchmark row.
  • min-of-N per document (N=15), quiet-machine re-bakes when the shared runner drifts.
  • A/B with byte-identical trees — no throughput change merges unless the parse output is unchanged; the tree identity is checked per keystroke in the incremental suite.
  • The honesty clause — losses publish with the same prominence as wins, with the profile of where the bytes go.

The harness, corpora, traces, corrupted cases, and dated receipts live in benchmarks/sota/ in the parsanol-rs repository — one command per suite to reproduce, per the receipts page.
