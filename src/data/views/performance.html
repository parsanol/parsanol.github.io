Performance, with receipts

Every number on this page is a dated, reproducible receipt — the harness, corpora, and corrupted cases are committed, every runner asserts full consumption before a timing counts, and losses publish with the same prominence as wins. That last rule is the clause that makes the rest of the page worth reading.

The honesty clause: tree-sitter is 37× faster on raw JSON throughput, and its incremental editing is a category parsanol has not won. Those rows sit at the top of this page on purpose — a benchmark suite you can't lose in public can't be believed when it wins.

Read it plainly: parsanol beats ANTLR by 1.7×; the LR-family engines lead on deterministic grammars, because a fixed LR table always beats a PEG's ordered-choice backtracking when the grammar lets one exist. The named lever, when a choice set is first-set disjoint (derivable at compile time), ordered choice collapses to indexed dispatch — the determinism fast path.

Error recovery — corrupted JSON

60 seeded corruption cases against the same corpus. This is where the artifact model shows: a declared resync policy turns recovery from an engine heuristic into data the grammar author controls.

metric parsanol 1.5.1 tree-sitter 0.25

The trade is architectural: tree-sitter recovers more suffix (it keeps reparsing after an error region), while parsanol's deepest-failure position tracks the corruption cause — 2.3× tighter diagnostic distance, and a truncation is located at the truncation, not reported as a root-ERROR at offset 0. Closing the suffix gap is the named recovery-envelope round on the json flavor.

Keystroke-scale incremental editing

200-keystroke edit traces over two document sizes. The row parsanol does not win, published because the honesty clause says so:

Parsanol's incremental path is correct — tree identity held at 400/400 keystrokes — but currently delivers no win: the memo retention rule drops the root entry on any length change, invalidating everything on value grammars. The innermost-container splice retention is the named fix. We publish the gap because a receipt you can't lose in can't be trusted when it wins.

The artifact economics

Performance is also the load path and the per-parse fixed cost — the numbers that decide whether shipping a grammar as data is practical:

The byte-checksum fast tier

One O(bytes) hash pass over the exact file bytes: ~5 ms on a 1.24 MB artifact, versus the 400–640 ms canonicalization the canonical checksum alone would cost on every load. Byte-level tamper detection before any parse work; older loaders fall back to the canonical tier unchanged.

The per-parse caches

Decoded entries and grammar analyses computed once for the parse-many pattern (PreparedGrammar): 7.5× on tiny-input parses — the setup/eval overhead that dominates small inputs, amortized.

The regression gate

Benchmark receipts ride CI with a regression gate: a train that loses numbers without a named cause doesn't merge. The receipts are evidence and a fence at the same time.

Measured, then honestly discarded

The arena-locality optimization was implemented, measured with Cachegrind counters, and falsified — recorded as a negative result. Perf claims here are survivorship-free.

Methodology

  • Shared corpus — every engine parses byte-identical documents; document hashes are committed per receipt.
  • Native runners — each engine runs its canonical binding; no cross-language handicaps for anyone.
  • Full-consumption proof before timing — a parse that stops early or errors is not a benchmark row.
  • min-of-N per document (N=15) — variance is reported, not averaged away.
  • The honesty clause — losses publish with the same prominence as wins, with the profile of where the bytes go.

The harness, corpora, traces, corrupted cases, and dated receipts live in benchmarks/sota/ in the parsanol-rs repository — one command per suite to reproduce, per the receipts page.
