Architecture

One grammar file compiles once into a checksummed artifact that five runtimes parse byte-identically. This page is the anatomy: the compile pipeline, the artifact envelope, the load path, the engines, the contract stack, and the proof layer that keeps every claim checkable.

The compile pipeline

A .parg file goes through one pass pipeline; what ships is the output, never the pipeline: 

.parg source
  │  one StringScanner pass (single tokenizer sweep)
  ▼
grammar tree (I-nodes)
  │  compile passes, each a pure rewrite:
  │    · skip injection        — declared trivia injects before terminals;
  │    │                         char-scan spans keep token spellings contiguous
  │    · left-recursion tiers  — expr = expr "*" expr / INT rewrites into
  │    │                         left-folding precedence tiers (the ANTLR 4 model)
  │    · Named wrapping        — edition 2 names every non-capturing reference;
  │    │                         capture-reachable rules compile unwrapped
  │    · resync baking         — declared recovery policies become deterministic
  │    │                       skip spans in the artifact
  │    · lint                  — shadowed alternatives and order dependence are
  │    │                         build failures, not runtime surprises
  │    · tests replay          — accept/reject/capture/example/shape run at bake;
  │                              a failing test fails the build
  ▼
artifact envelope (checksummed JSON)

The artifact carries the original source inside, so any runtime can rebuild atoms without the file — and the compiler stamps a validated receipt (lint errors always 0, lint warnings, embedded test totals, self-test flag) so "is this grammar validated" is an inspectable envelope field covered by both digests.

The envelope anatomy

The wire shape (parsanol-tree/v2) is the portability contract. Every field, and what attests it:

fieldroleattested by
shapethe wire contract itself — a shape bump is a new engine familychecked first, on load

The split is deliberate: the canonical checksum attests content (stable across re-bakes by a newer compiler); the byte_checksum attests bytes (fast, tamper-proof); the semantics_hash attests behavior — so a freshness gate can tell "re-baked by a newer compiler" from "the grammar changed" without re-verifying anything by hand.

The load path

load(artifact)
  │  1. byte tier      — one O(bytes) hash pass, no parse: byte_checksum must
  │                       match the exact file bytes (~5 ms on a 1.24 MB artifact).
  │                       A flipped bit, wrong file, or CRLF-mangled checkout is
  │                       rejected before any parse work.
  │  2. canonical tier  — canonicalized-envelope checksum (the cross-engine contract);
  │                       loaders that only see a parsed envelope fall back here
  │  3. edition + shape — removed spellings reject loudly with the recompile
  │                       instruction, before the checksum is even verified
  │  4. tests replay    — the embedded assertions run on the loading engine
  ▼
ready: parse / parse_and_bind / render / derive

Refusals name the producer: a canonical-checksum mismatch raises ChecksumCompilerMismatch, carrying which compiler produced the artifact and what the loading engine expected — the same loud-boundary discipline everywhere.

The engines

The same artifact runs on three parse engines, pinned byte-identical by the conformance corpus and the differential suite:

Packrat interpreter

Memoized PEG interpretation over arena-allocated atoms. O(n) parsing, zero-copy node construction. The reference semantics path.

Bytecode VM

The compiled atoms lower to VM bytecode — the engine behind the wasm, TypeScript, and Python tiers. The short-parse class the repro gates caught is fixed here.

Native bindings

Ruby's native tier (C-API extension and FFI cdylib) and the Rust crate share the same core. PreparedGrammar computes the analyses once for the parse-many pattern.

A ResourceGovernor bounds recursion depth, time, and memory; and the tier boundary is a contract, not a leak — grammars using runtime state (state/set/switch atoms, custom Ruby classes) are rejected loudly by the Rust, wasm, and TS engines instead of mis-parsing. Portable exceptions exist where the semantics allow them (ASCII-insensitive state matching ships as a wire op).

The contract stack

  • Engine-linked versioning — the engine is 1.5.x; runtimes follow as {engine-semver}.{runtime-digit} (the gem is 1.5.x.0, wasm/npm 1.5.x). Engine 1.x is the stability declaration: exhaustive-enum changes are major, new surface lands behind non-exhaustive variants.
  • The semver gate — release automation refuses a non-major bump when an exhaustive variant grows; capture renames are major, new alternatives minor, literal fixes patch — classified by parg diff.
  • Grow-with-minor — new preprocess ops and envelope members stamp a version field (binding_version); old engines refuse higher levels, so a step they don't know can never run silently wrong.
  • Feature-status metadata — the guide marks each feature shipped / partial / specified with the version, so doc consumers can derive truth mechanically.
  • The freshness gate — CI compares semantics_hash, not bytes: producer-only re-bakes warn and pass; a grammar change fails the build.

The proof layer

SOTA is a claim until it publishes evidence. The layer that makes the claims checkable:

The conformance corpus

Per-feature pinned cases (the semantics laws, the envelope-members matrix) replayed through every engine — byte-identical trees, captures, and bound maps.

The differential suite

One grammar, five runtimes, identical outputs — enforced by nightly differentials and the parity gates (the corpus matrix makes an unrecorded envelope member a CI failure).

The fuzzing gate

A scheduled hours-long fuzz run; it found a real panic on its first sweep, and the fix rode the next train.

Receipts + the manifest

Dated benchmark receipts publish losses with the same prominence as wins (see Performance); ENGINE-COMPAT.json pairs engine commits to package versions, and a CI checker fails when a train rides without recording itself.

Repro gates are first-class: when a real grammar hits an engine bug (the VM short-parse class, the trivia-in-keyword mask), the failing case lands as a gated test before the fix — the bug can't silently reopen.

Every tier loads the same artifact, verifies the same digests, replays the same tests, and returns the same trees — the identity is enforced by the corpus, not promised.
